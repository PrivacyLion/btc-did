Enterprise Integration Guide

Last updated: April 2026 · Estimated integration time: 2-4 hours

Overview

SignedByMe provides passwordless, privacy-preserving authentication via standard OIDC. Your users prove membership in your allowlist using zero-knowledge proofs — without revealing which member they are.

Integration requires four steps:

  1. Register your enterprise and get API credentials
  2. Display login QR code / deep link
  3. Listen for proof events on NOSTR
  4. Verify proof and receive OIDC id_token

Prerequisites

  • Client ID — Assigned during enterprise registration
  • API Key — For authenticating verification requests
  • Strike API Key — For paying Lightning invoices (or your own LN node)
  • NOSTR Relay Access — WebSocket connection to wss://relay.privacy-lion.com

Don't have credentials? Contact enterprise@privacy-lion.com to register your enterprise.

Step 1: Display Login QR Code

Generate a login session entirely client-side. No API call required.

Deep Link Format

signedby://{client_id}/{nonce}/{amount_sats}
Parameter Description
client_id Your enterprise identifier (e.g., "acme")
nonce 32-character hex string (16 random bytes)
amount_sats Satoshis to pay user on successful login

Example

// Generate nonce
const nonce = Array.from(crypto.getRandomValues(new Uint8Array(16)))
    .map(b => b.toString(16).padStart(2, '0')).join('');

// Build deep link
const deepLink = `signedby://acme/${nonce}/100`;

// Display as QR code
new QRCode(document.getElementById('qr'), {
    text: deepLink,
    width: 256,
    height: 256
});

Step 2: Subscribe to NOSTR Relay

Connect to the relay and subscribe to kind 28101 events tagged with your nonce. The user's app will publish a proof event when they scan and authenticate.

Subscription Filter

const ws = new WebSocket('wss://relay.privacy-lion.com');

ws.onopen = () => {
    ws.send(JSON.stringify([
        'REQ',
        'login-sub',
        {
            kinds: [28101],
            '#nonce': [nonce]
        }
    ]));
};

ws.onmessage = (event) => {
    const msg = JSON.parse(event.data);
    if (msg[0] === 'EVENT' && msg[2].kind === 28101) {
        handleProofEvent(msg[2]);
    }
};

Proof Event Structure (kind 28101)

{
    "kind": 28101,
    "pubkey": "user_npub_hex",
    "created_at": 1714089600,
    "tags": [
        ["nonce", "your_nonce_here"],
        ["c", "your_client_id"]
    ],
    "content": {
        "proof": "base64_groth16_proof",
        "public_outputs": {
            "npub": "npub1...",
            "merkle_root": "0x..."
        },
        "invoices": {
            "user_invoice": "lnbc100n1...",
            "operator_invoice": "lnbc10n1..."
        }
    },
    "id": "event_id",
    "sig": "schnorr_signature"
}

Step 3: Pay Lightning Invoices

The proof event contains two BOLT11 invoices. You must pay both:

  • user_invoice — Payment to the user (90% of amount)
  • operator_invoice — Platform fee (10% of amount)

Using Strike API

async function payInvoice(bolt11, strikeApiKey) {
    // Create quote
    const quoteRes = await fetch('https://api.strike.me/v1/payment-quotes/lightning', {
        method: 'POST',
        headers: {
            'Authorization': `Bearer ${strikeApiKey}`,
            'Content-Type': 'application/json'
        },
        body: JSON.stringify({
            lnInvoice: bolt11,
            sourceCurrency: 'BTC'
        })
    });
    const quote = await quoteRes.json();
    
    // Execute payment
    const payRes = await fetch(
        `https://api.strike.me/v1/payment-quotes/${quote.paymentQuoteId}/execute`,
        {
            method: 'PATCH',
            headers: { 'Authorization': `Bearer ${strikeApiKey}` }
        }
    );
    const payment = await payRes.json();
    
    return payment.preimage; // Hex-encoded preimage
}

Important: Save both payment preimages. You'll need them for verification.

Step 4: Verify and Get Token

Submit the proof and payment preimages to receive an OIDC id_token.

API Endpoint

POST https://api.beta.privacy-lion.com/v1/login/verify
Content-Type: application/json
X-API-Key: your_api_key

{
    "proof": "base64_groth16_proof",
    "public_outputs": {
        "merkle_root": "0x...",
        "npub": "npub1..."
    },
    "user_invoice": "lnbc100n1...",
    "operator_invoice": "lnbc10n1...",
    "preimage_hex": "user_payment_preimage",
    "operator_preimage_hex": "operator_payment_preimage"
}

Response

{
    "id_token": "eyJhbGciOiJSUzI1NiIs...",
    "token_type": "Bearer",
    "expires_in": 3600
}

ID Token Claims

Claim Description
sub User's npub (consistent per enterprise, unlinkable across enterprises)
iss https://api.beta.privacy-lion.com
aud Your client_id
membership_root Merkle root user proved membership against
payment_verified true (Lightning payment confirmed)

User Enrollment

Before users can log in, they must be enrolled in your Merkle tree. Enrollment is a separate flow where you authorize a user to join your allowlist.

Enrollment QR Format

signedby://enroll/{client_id}/{nonce}?exp={unix_timestamp}

Kind 28200: Enrollment Authorization

Before displaying the enrollment QR, you must publish a kind 28200 event signed with your enterprise NOSTR key. This authorizes the enrollment session. 

{
    "kind": 28200,
    "pubkey": "your_enterprise_npub_hex",
    "created_at": 1714089600,
    "tags": [
        ["nonce", "enrollment_nonce"],
        ["c", "your_client_id"]
    ],
    "content": {
        "client_id": "your_client_id",
        "expires_at": "2026-04-19T12:00:00Z"
    }
}

NIP-05 Verification: Your enterprise NOSTR pubkey should be published at yourdomain.com/.well-known/nostr.json for user apps to verify authenticity.

Security Considerations

  • Nonce uniqueness: Generate a fresh nonce for each login. Never reuse nonces.
  • Session timeout: Nonces should expire after 5 minutes. Stop listening after expiry.
  • Verify the proof: Always submit to /v1/login/verify. Don't trust the NOSTR event alone.
  • HTTPS only: Never load SignedByMe integration over HTTP.
  • Protect API keys: Keep your API key server-side. Never expose in client code.
