What is SignedByMe?

SignedByMe is a self-signing digital signature. Not signed by Google. Not signed by Okta. Signed by you — on your device, with your key, under your control.

🔐

Self-Sovereign Identity

Your cryptographic key is created on-device and stored in hardware-backed secure storage. It never leaves your phone. No one issues it. No one can revoke it. You own it.

🛡️

Zero-Knowledge Proof

Prove you're authorized without revealing who you are. Enterprises get a boolean — "this person is approved" — without learning which person. Mathematically impossible with traditional signatures.

⚡

Bitcoin-Backed Auth

Every login is backed by a real Lightning Network payment. You earn sats for authenticating. Bots can't spam logins that cost money. The payment is cryptographic proof.

For AI Agents

Integrate SignedByMe to give your agent cryptographically verifiable identity. Standard SDK. Four API calls. Works with any enterprise that accepts OIDC.

Rust 
use signedby_sdk::{SignedByClient, LoginRequest};

// Initialize with owner's delegated credential
let client = SignedByClient::new(credential_path)?;

// Authenticate to an enterprise
let token = client.login(LoginRequest {
    client_id: "acme-corp",
    nonce: &session_nonce,
}).await?;

// token.id_token is a standard OIDC JWT
// Enterprise verifies via /.well-known/jwks.json

For Enterprises

Add "Sign in with SignedByMe" to your app. Your users are cryptographically verified with zero PII. No breach risk. No passwords. Standard OIDC integration.

4 API Calls

Same integration complexity as Okta or Auth0.

Zero PII

Private Allowlists

Control who can log in without knowing who logged in.

Integration Flow 
1. Generate nonce, display QR: signedby://{client_id}/{nonce}/{sats}
2. Subscribe to NOSTR relay for proof event (kind 28101)
3. On proof: pay Lightning invoices, call POST /v1/login/verify
4. Receive OIDC id_token with sub=npub (user's pseudonymous ID)
